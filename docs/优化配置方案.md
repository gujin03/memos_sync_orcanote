## 🔴 高优先级（数据正确性，行为变更）

### ① 增量同步「只增不改」
- **位置**：L359–361
- **现状代码**：
  ```ts
  if (existingBlocks.has(memoId)) {
    return
  }
  ```
- **问题**：增量同步命中已有块直接 `return`。但 Memos 端编辑内容/标题后，`updated_ts` 仍会命中被拉回，却因已存在而跳过 → **Memos 的编辑永远同步不进 Orca**，只能靠全量同步兜底。
- **目标行为**：命中后改为「更新」而非「跳过」——刷新标题块文本与 Memos 原始标签（正文 diff 复杂度高，v1 仅更新标题+标签，正文标记为 TODO）。
- **改动要点**：
  1. 在增量查重 Map（L215–229）中，value 由 `DbId`（rootId）扩展为 `{ rootId: DbId; titleId?: DbId }`，构建时通过 `orca.state.blocks[rootId].children` 定位标题块（第 2 层，非链接块）。
  2. `syncMemo`（L359）命中时，不 `return`，改为 `updateMemo(...)`：
     - 标题块：用 `core.editor.setContent` / `setBlock` 更新文本为最新 `titleText`。
     - Memos 原始标签：diff 当前块标签与 `memo.tags`，增删差额。
     - 根块 ID 属性保持不变（仍为 `memoId`）。
  3. 正文块（第 3 层）更新：v1 暂不做（避免 diff 复杂度），在代码注释标 `TODO: 正文增量更新`。
- **影响范围**：增量同步现可回写编辑；不改变全量同步路径。
- **验收标准**：
  - 在 Memos 改一条已同步 memo 的标题 → 增量同步后 Orca 标题块文本更新。
  - 增删 Memos 标签 → Orca 标题块标签同步增删。
  - 不改标题只改正文 → 至少标题/标签同步（正文视实现）。

### ② 部分失败被「假装成功」
- **位置**：L250（回写 `lastSyncTime`）+ L455–457（`syncMemo` catch）+ L240–247（主循环）
- **现状代码**：
  ```ts
  // L455-457
  } catch (e) {
    console.error("MEMOS SYNC: syncMemo error for", memo.name, e)
  }
  // L250（无论是否有失败都执行）
  await orca.plugins.setData(pluginName, "lastSyncTime", Date.now())
  ```
- **问题**：单条 `syncMemo` 抛错被 catch 静默吞掉（不抛、不计数）；主循环（L240）`await syncMemo(...)` 不捕获失败；`lastSyncTime` 始终 `Date.now()` → 失败数据之后的增量窗口被「跳过」，**失败数据永不重试、静默丢失**。
- **目标行为**：累计失败数，有任何失败就**不推进** `lastSyncTime`（保留旧值，下次重跑会重拉已成功项但命中查重跳过）；结束提示 `成功 N 条，失败 M 条`。
- **改动要点**：
  1. `syncMemo` 失败时不静默：改为 `return false`（或在 catch 中 `return false`），成功 `return true`。
  2. 主循环（L240–247）累加 `failedCount += syncMemo(...) ? 0 : 1`。
  3. 回写逻辑（L250 附近）：
     ```ts
     if (failedCount === 0) {
       await orca.plugins.setData(pluginName, "lastSyncTime", Date.now())
     }
     // 有失败则不更新 lastSyncTime，下次重跑补回
     ```
  4. 结束 `orca.notify` 文案区分成功/失败计数（与 L252 合并）。
- **影响范围**：影响增量同步的幂等性与数据完整性；需与 ⑦ 合并实现。
- **验收标准**：
  - 人为制造 1 条失败（如临时令某 memo 内容解析异常）→ 结束提示含失败数，且 `lastSyncTime` 未推进。
  - 下次增量重跑 → 该条被补回，其他已成功项命中查重跳过（无重复）。

### ③ 全量删除异常吞掉 + 上限硬编码
- **位置**：L192（`pageSize: 100000`）+ L206–208（catch 仅 `warn`）
- **现状代码**：
  ```ts
  // L192
  pageSize: 100000,
  // L201-209
  for (let i = 0; i < allExistingIds.length; i += 100) {
    try {
      await orca.commands.invokeEditorCommand(
        "core.editor.deleteBlocks", null, allExistingIds.slice(i, i + 100),
      )
    } catch (e) {
      console.warn("MEMOS SYNC: Failed to delete batch", e)  // 仅 warn，继续下一批
    }
  }
  ```
- **问题**：删除中途失败 → 旧块残留 + 新建新块 = **重复块（孤儿）**；`pageSize:100000` 上限，历史超 10 万条则取不全、删不净。
- **目标行为**：删除失败要 `notify`/计数并考虑中断（避免半删导致孤儿）；查询用翻页确保取全。
- **改动要点**：
  1. 查询取全（L190–193）：将单次 `query` 改为翻页循环（while `nextPageToken`），累加 `allExistingIds`，消除 10 万上限截断。
  2. 删除失败（L206–208）：改为计数 + `orca.notify("warn", ...)`；若失败，建议**中断**全量删除并整体报错（避免孤儿），由用户决定是否重试。
  3. 删除完成后校验 `allExistingIds.length` 与已删数一致（可选断言）。
- **影响范围**：仅全量同步路径；增量不受影响。
- **验收标准**：
  - 历史 > 10 万条时仍能取全并删净（或至少不静默截断并提示）。
  - 删除中途模拟失败 → 提示失败数，不残留孤儿块。

## 🟡 中优先级（健壮性）

### ④ memoId 提取脆弱
- **位置**：L356 `const memoId = memo.name.replace("memos/", "")`
- **问题**：`name` 为空或非 `memos/xxx` 格式时，返回空串或错误字符串 → 查重/ID 属性错乱。
- **目标行为**：空 `name` 或解析失败 → 安全 skip + 计数，不污染查重表。
- **改动要点**：
  ```ts
  const memoId = (memo.name?.split("/").pop() || memo.name || "").trim()
  if (!memoId) { failedCount++; return false }
  ```
- **验收标准**：构造一条 `name` 为空/异常格式的 memo → 同步不崩、被安全跳过并计入失败数。

### ⑤ xhr 无超时 + 错误不分类
- **位置**：L321–345 `xhrRequest()`
- **问题**：无 `xhr.timeout`；401（token 错）/ 400（filter 错）/ 网络错 混为同一提示，排错困难。
- **目标行为**：加超时；按 `status` 给差异化中文提示，并向上抛错由 `syncMemos` catch 统一 notify。
- **改动要点**：
  ```ts
  xhr.timeout = 30000
  xhr.ontimeout = () => reject(new Error("请求超时，请检查 memos 服务是否可达"))
  // onreadystatechange 中按 status 分类：
  // 401 → "API Token 无效或已过期"
  // 400 → "请求参数错误（filter 语法）"
  // 其他 → 现有文案
  ```
- **验收标准**：用错误 token 触发 → 提示「API Token 无效或已过期」而非笼统错误。

### ⑥ 增量去重键用 `b.text` 兜底 + 只留首个
- **位置**：L222 `const memoId = (idProp?.value as string) || b.text` + L224 只保留首个
- **问题**：无 ID 属性的块（手动创建/旧版导入）误用正文去重 → 误判；重复块只留第一份会漏删。
- **目标行为**：严格只用 ID 属性参与查重；无 ID 的块单独评估，不混入查重表。
- **改动要点**：
  ```ts
  const idProp = b.properties?.find(p => p.name === "ID")
  if (!idProp?.value) {
    noIdBlocks.push(b)  // 单独标记，后续人工/模糊处理
    continue
  }
  const memoId = idProp.value as string
  if (memoId && !existingBlocks.has(memoId)) {
    existingBlocks.set(memoId, { rootId: b.id })
  }
  ```
- **验收标准**：库中存在无 ID 属性的旧块 → 不被误判为已同步、不漏删对应 memo。

### ⑦ 单条 `syncMemo` 错误静默
- **位置**：L455–457（与 ② 合并实现）
- **目标行为**：同 ②——catch 后 `return false`，由主循环统计并 `notify`，不再静默。
- **说明**：本项不单独成块，随 ② 一并落地。

## 🔴 追加项 ⑪：Memos 引用语法（`> `）未渲染为 quote 块（2026-10-18 实测）

### 现象
从 Memos 同步的 memo，正文里的 Markdown 引用行（`> ...`）在 Orca 中显示为**带字面 `> ` 前缀的普通文本块**，没有渲染成引用样式。用户截图对应块 ID `36481`。

### 根因（DB 实证，非推测）
- `syncMemo` 把 memo 正文按 `\n` 切成段落（L374–376），每段**一律**用 `insertBlock` 插入为纯文本片段 `[{t:"t", v:para}]`（L429–435），**没有传 `repr`** → 块类型默认 `{"type":"text"}`。
- 实测 block `36481`：
  - `content = [{"t":"t","v":"> 我之所以能坚持做这件事..."}]` —— `> ` 被当正文原样保留。
  - `BlockProperty.name='_repr'` → `{"type":"text"}`。
- Orca 1.x 的引用块**真实类型是 `{"type":"quote2"}`**（本库有 138 个），**不是** `ORCA_API_REFERENCE.md` 里写的 `"quote"`（该文档同时把列表写成 `bullet`/`numbered`，实际是 `ul`/`ol`，表格是 `table2`，文档已过时）。
- 结论：**不是 Memos 问题、也不是同步链路问题，是插件没做 Markdown 块级解析**，把所有段落都当 plain text。

### 修复方案（推荐 A）

**方案 A（已实施，`fc71971` + `212def1`）**：识别引用行、剥离 `> ` 前缀，插入时创建 **quote2 容器块 + text 子块**。

> ⛔ **重要修正（2026-10-18 二次实测）**：第一版实现直接把正文当**内联 content** 传给 quote2（`insertBlock(..., [{t:"t",v:text}], {type:"quote2"})`），结果引用块**显示为空**、只有「引述」占位符。
> **根因：Orca 的 `quote2` 是容器块，只渲染自己的子块，不渲染内联 content。**
> 库内 149 个 quote2 的实证：`content=NULL` 的有 125 个（其中 112 个恰有 1 个 text 子块＝原生引用形态）；`content` 非空的有 24 个且**全部子块数=0**——正是第一版 bug 的产物。
> ⇒ **正确写法：先建空 quote2（content 传 `null`），再把正文作为 text 子块插进去。**

改动点 1 — 正文循环（现 L424–505）：
```ts
const QUOTE_RE = /^>\s?/
let prevContentId: DbId | null = null
let i = 0
while (i < bodyParas.length) {
  const para = bodyParas[i].trim()
  const isQuote = QUOTE_RE.test(para)
  let text: string
  if (isQuote) {
    const lines: string[] = []
    while (i < bodyParas.length && QUOTE_RE.test(bodyParas[i].trim())) {
      lines.push(bodyParas[i].trim().replace(QUOTE_RE, ""))
      i++
    }
    text = lines.join("\n")          // 连续引用行合并
  } else { text = para; i++ }
  if (!text.trim()) continue

  const anchor = prevContentId ? orca.state.blocks[prevContentId] : titleBlock
  const position = prevContentId ? "after" : "firstChild"

  if (isQuote) {
    // 1) 空 quote2 容器（content 必须为 null）
    const quoteId = await orca.commands.invokeEditorCommand(
      "core.editor.insertBlock", null, anchor, position, null, { type: "quote2" },
    )
    if (!quoteId) continue
    // 2) 正文作为 text 子块放进容器（quote2 渲染的正是子块）
    const quoteBlock = orca.state.blocks[quoteId]
    if (quoteBlock) {
      await orca.commands.invokeEditorCommand(
        "core.editor.insertBlock", null, quoteBlock, "lastChild",
        [{ t: "t", v: text }], { type: "text" },
      )
    }
    prevContentId = quoteId
  } else {
    const paraId = await orca.commands.invokeEditorCommand(
      "core.editor.insertBlock", null, anchor, position,
      [{ t: "t", v: text }], { type: "text" },
    )
    if (paraId) prevContentId = paraId
  }
}
```

改动点 2 — 标题提取（L375）：标题若以 `> ` 开头也应剥离：
```ts
const titleText = (paragraphs[0] || memoId).replace(/^>\s?/, "").substring(0, 100)
```

⚠️ **调试该问题时读库必带 WAL**：`?immutable=1` 会忽略 `-wal` 读到旧快照（据此曾误判「内容丢失」）。正解＝复制 `sample.db` + `sample.db-wal` + `-shm` 到 /tmp 再普通连接打开。

**已同步数据补救**：插件增量模式命中已有块会直接跳过（见 ①），因此修复后需**跑一次全量同步**（删旧块重建），才能修正历史块 `36481` 这类错误块。

### 方案 B（更彻底，进阶段 M4，待实测）

**结论：原理正确、API 已实证存在，但调用签名需实测、Memos 语法需预处理——列为「待实测验证」的进阶段，不替换已上线的方案 A。**

#### 机制（已实证，非推测）
- `core.editor.batchInsertHTML` **真实存在**，asar 注册体为：
  ```js
  registerEditorCommand("core.editor.batchInsertHTML", async ([mr,,ur],pr,Ji,Uo)=>{
    const Da = new DOMParser().parseFromString(Uo,"text/html");
    const uu = await convertHTMLToReprs(Da.body);   // HTML → 原生块 repr
    if (uu.length===0) return null;
    const hu = orca.nav.findViewPanel(mr, orca.state.panels);
    ...
    return { ret: await hu.viewState.editor.invokeCommand("core.editor.batchInsertReprs", ur, pr, Ji, uu) };
  })
  ```
  即：**HTML 字符串 → `DOMParser` → `convertHTMLToReprs(body)` 转原生 repr（quote2 / heading / ul / ol / li / code …）→ `batchInsertReprs` 落库**。
- `convertHTMLToReprs` 是 Orca **粘贴 / HTML 导入**复用的核心转换器（asar 中出现 7 次），质量有保证；`BLOCKQUOTE` / `STRONG` / `CODE` / `PRE` / `UL` / `OL` / `LI` / `EM` 在 asar 中大量出现，说明标签映射齐全。
- 这正是 MCP `insert_markdown` 的底层实现（`ORCA_API_REFERENCE.md` L502：`insert_markdown` → `invokeEditorCommand("core.editor.batchInsertHTML", …)`）。

#### 与方案 A 的关系
- 方案 A（已上线 `fc71971`+`212def1`）：手动识别 `> `、硬编码 `quote2` 容器 + text 子块。**已验证可用**，但只覆盖引用，粗体/链接/标题/列表仍是纯文本。
- 方案 B：把整段 Markdown 交给 Orca 自己解析，**顺带修好标题/列表/粗体/链接/代码**，且**不硬编码块类型**（随 Orca 版本演进自动适配 `quote2` 这类命名）。代价是引入 markdown→HTML 依赖、且要处理 Memos 的语法特性。

#### 风险 / 前置条件（必须解决才能作为默认路径）
1. **⚠️ 调用签名需实测**：`batchInsertHTML` 注册体把第一个参数解构成数组 `[mr,,ur]`（即 `[panelId, _, refBlock]`），后续依次是 `position`、`Ji`、`html`——与 `insertBlock` 直观的 `(panelId, refBlock, position, content, repr)` 不同，参数顺序不直观。**必须先用一次真实调用（或对齐 MCP `insert_markdown` 的实际传参）确认，否则会插错位置或插成空**。
2. **⚠️ Memos 语法 ≠ 标准 Markdown，需预处理**（`marked` 会误判）：
   - `#tag`（Memos 标签）→ 被当作 H1 标题，需先转义或保留为文本；
   - `[[wikilink]]` / `@mention` → 非标准，需预处理为链接或原样保留；
   - `- [ ]` / `- [x]` 任务清单 → `marked` 默认不渲染 checkbox，需扩展或预处理；
   - 软换行 vs 段落划分会影响 `<p>` / `<br>` 生成。
3. **依赖体积**：需引入 `marked`（或改用 Orca 自带 markdown 解析）进 bundle；vite 已 external `react`/`react-dom`/`valtio`，`marked` 应可正常打包，但需验证构建。
4. **回归风险**：整条内容路径更换是**大改动**，必须有「方案 A 作为回退」+ 全量同步回归测试。
